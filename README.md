# WebPIKASO — Company Website

سایت شرکتی وب پیکاسو (تیم توسعه‌ی نرم‌افزار)، ساخته‌شده با **Next.js (App Router) + React + TypeScript + Tailwind CSS**.

## راه‌اندازی اولیه

```bash
npm install
cp .env.example .env.local
```

بعد `.env.local` رو باز کن و مقادیر زیر رو ست کن:
- `USER_SESSION_SECRET` — یه رشته‌ی رندوم و طولانی برای امضای نشست همه‌ی حساب‌ها (هم مشتری، هم تیم) — مثلاً با `openssl rand -hex 32` بسازش.
- `MONGODB_URI` — رشته‌ی اتصال کلاستر MongoDB Atlas خودت (بخش «اتصال به MongoDB Atlas» پایین همین فایل رو ببین).
- `BLOB_READ_WRITE_TOKEN` — فقط اگه می‌خوای آپلود عکس بلاگ یا پیوست چت تیم رو محلی تست کنی (بخش «آپلود فایل (Vercel Blob)» پایین رو ببین)؛ بدونش هم بقیه‌ی سایت مشکلی نداره.

## اتصال به MongoDB Atlas

این پروژه دیتاش (کاربرها، سفارش‌ها، تیکت‌ها، چت تیم، وبلاگ، CRM، تسک‌ها) رو تو **MongoDB Atlas** نگه می‌داره — نه فایل محلی — برای همینه که روی پلتفرم‌های سرورلس مثل Vercel هم بدون مشکل کار می‌کنه.

1. تو [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas) یه حساب رایگان بساز (یا وارد شو).
2. یه **Cluster** جدید بساز (پلن رایگان M0 برای این پروژه کافیه).
3. تو بخش **Database Access** یه کاربر دیتابیس با یوزرنیم/پسورد بساز.
4. تو بخش **Network Access** یه IP Access List اضافه کن — برای این‌که هم از سیستم خودت هم از Vercel وصل بشه، ساده‌ترین راه گزینه‌ی **Allow Access from Anywhere** (0.0.0.0/0) هست (Vercel آی‌پی ثابت نداره).
5. رو خود Cluster بزن **Connect → Drivers**، و رشته‌ی اتصال (چیزی شبیه `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`) رو کپی کن.
6. `<user>` و `<password>` رو با اطلاعات کاربر دیتابیسی که ساختی جایگزین کن، و بعد از هاست‌نیم یه اسم دیتابیس اضافه کن (مثلاً `.../webpikaso?retryWrites=...`) — همین رشته‌ی کامل می‌شه مقدار `MONGODB_URI`.
7. این مقدار رو تو `.env.local` بذار (برای اجرای محلی) و تو تنظیمات محیطی Vercel هم (برای دیپلوی — پایین توضیح داده شده).

اولین باری که سایت اجرا بشه، `lib/db.ts` خودش کالکشن‌ها رو تو دیتابیس Atlas می‌سازه — نیازی به اجرای اسکریپت migration جدا نیست.

## اتصال به Redis (کش + محدودسازی نرخ درخواست)

پروژه از Redis برای دو تا کار استفاده می‌کنه (`lib/redis.ts`):

- **کش کردن** خواندن‌های پرتکرار از دیتابیس — لیست پروژه‌های پورتفولیو و پست‌های منتشرشده‌ی وبلاگ (۶۰ ثانیه) — تا فشار روی MongoDB کم بشه.
- **محدودسازی نرخ ارسال فرم‌ها** (فرم تماس، ثبت سفارش پلن) به‌صورت مشترک بین همه‌ی instance های سرورلس — قبلاً این محدودیت فقط تو حافظه‌ی همون یک instance بود و با هر ری‌استارت پاک می‌شد.

راه‌اندازی:

1. یه دیتابیس Redis بساز — ساده‌ترین گزینه برای Vercel، **Upstash Redis** هست (از Vercel Marketplace یا مستقیم از [upstash.com](https://upstash.com) — پلن رایگانش برای این پروژه کافیه). هر سرویس Redis دیگه (Redis Cloud، یه سرور Redis خودت) هم کار می‌کنه.
2. رشته‌ی اتصال رو کپی کن (چیزی شبیه `rediss://default:<password>@<host>:<port>`).
3. بذارش تو متغیر محیطی `REDIS_URL` — هم تو `.env.local` (اجرای محلی) و هم تو تنظیمات محیطی Vercel.

اگه `REDIS_URL` تنظیم نشه، سایت بدون خطا کار می‌کنه — فقط کش و محدودیت نرخ می‌رن روی حالت قبلی (حافظه‌ی محلی همون instance)، دقیقاً مثل رفتار قبل از اضافه شدن Redis.

## بهینه‌سازی عکس‌ها و کش مرورگر

- همه‌ی عکس‌های استاتیک سایت (لوگو، اسکرین‌شات‌های پورتفولیو، عکس‌های هیرو) به **WebP** تبدیل شدن (حدود ۷۵٪ کاهش حجم نسبت به نسخه‌ی قبلی jpg/png).
- عکس‌هایی که کاربر بعداً آپلود می‌کنه (کاور پست وبلاگ، پیوست چت تیم — که رو Vercel Blob ذخیره می‌شن) از طریق کامپوننت `next/image` سرو می‌شن؛ Next خودش موقع نمایش، بر اساس مرورگر کاربر، فرمت WebP/AVIF تولید می‌کنه — نیازی به تبدیل دستی نیست (تنظیمش تو `next.config.js` انجام شده).
- فایل‌های استاتیک (`/logo.webp`, `/work/*`, `/screenshots/*`, دموهای پورتفولیو `/projects/*.html`) هدر `Cache-Control` طولانی‌مدت گرفتن تا مرورگر و هر CDN جلوی سایت، دیگه هر بار دوباره درخواستشون نکنه.

## حالت روشن / تاریک

- دکمه‌ی تعویض تم (آیکون خورشید/ماه) تو نوار بالا هست — هم دسکتاپ هم موبایل.
- پیش‌فرض سایت همیشه **روشنه**؛ فقط وقتی کاربر خودش تاریک رو انتخاب کنه، تو `localStorage` ذخیره می‌شه و همون رو تو بازدیدهای بعدی نگه می‌داره.
- رنگ‌های سایت (`ink`، `dim`، `canvas`) از طریق CSS variable تعریف شدن (تو `app/globals.css`)، برای همینه که همه‌جای سایت با یه کلاس `.dark` رو `<html>` خودکار عوض می‌شن — لازم نیست هر کامپوننت جدا استایل تاریک بگیره.

## حساب کاربری (ورود / ثبت‌نام) و داشبورد مشتری

- آدرس `/account` صفحه‌ی ورود/ثبت‌نام رو نشون می‌ده. از `md` به بالا یه پنل دونیمه‌ست: نیمی فرم فعال (ورود یا ثبت‌نام)، نیم دیگه یه پنل سرمه‌ای با یه متن و دکمه («حساب نداری؟» / «قبلاً حساب ساختی؟») که با کلیک روش، کل پنل با انیمیشن اسلاید بین دو حالت جابه‌جا می‌شه. زیر `md` (موبایل) همون تب ساده‌ی قبلی می‌مونه چون جا برای پنل دونیمه نیست.
- تو ثبت‌نام، اسم + **شماره موبایل** + رمز عبور گرفته می‌شه و تو جدول `users` ذخیره می‌شه (با نقش پیش‌فرض `customer`). شماره موبایل چه با ارقام فارسی (۰۹۱۲۳۴۵۶۷۸۹) تایپ بشه چه انگلیسی (09123456789)، هر دو قبول می‌شه — تبدیل رقم فارسی به انگلیسی تو `lib/auth.ts` (`toEnglishDigits`) انجام می‌شه، قبل از اعتبارسنجی و ذخیره. هر جا شماره موبایل نمایش داده می‌شه (پروفایل، لیست کاربرهای داشبورد ادمین) با `toPersianDigits` به فرمت فارسی برمی‌گرده.
- **رمز عبور باید حداقل ۸ کاراکتر باشه و شامل حرف بزرگ، حرف کوچک، عدد و کاراکتر خاص بشه** (قوانین تو `lib/passwordPolicy.ts` تعریف شدن و هم سمت سرور (`app/account/actions.ts`) هم سمت کلاینت چک می‌شن). زیر فیلد رمز عبور تو فرم ثبت‌نام، یه نوار قطعه‌قطعه و یه چک‌لیست هست (`components/PasswordStrengthMeter.tsx`) که هر قانونی که رعایت بشه سبز می‌شه. یه فیلد «تکرار رمز عبور» هم هست که تا با رمز اول یکی نباشه، دکمه‌ی ساخت حساب غیرفعال می‌مونه.
- رمز عبور هش می‌شه (`scrypt` + salt رندوم)، هیچ‌جا متن ساده ذخیره نمی‌شه.
- نشست کاربر با یه کوکی httpOnly امضاشده (HMAC با `USER_SESSION_SECRET`) نگه داشته می‌شه.
- بعد از ورود، `/account` دیگه فقط یه کارت پروفایل نیست — یه داشبورد واقعیه (`UserDashboard.tsx`) با دو تب:
  - **پروژه‌های درخواستی** — هر درخواستی که از فرم تماس صفحه‌ی اصلی فرستاده باشه *در حالی که لاگین بوده*، این‌جا لیست می‌شه (جدول `inquiries` یه ستون `user_id` داره که موقع ارسال فرم، اگه کاربر لاگین باشه، پر می‌شه).
  - **تیکت‌ها** — یه فرم برای ثبت تیکت جدید (موضوع + توضیحات) به‌علاوه‌ی لیست تیکت‌های قبلی خودش با وضعیت باز/بسته. تیکت‌ها تو جدول جدید `tickets` ذخیره می‌شن (`lib/db.ts`: `createTicket`, `getTicketsByUserId`).

## نقش‌ها و داشبورد تیم (`/dashboard`)

هر کاربر تو جدول `users` یه `role` داره: `customer` (پیش‌فرض، همون مشتری‌های `/account`)، `developer` (عضو تیم برنامه‌نویسی) یا `admin` (دسترسی کامل).

**دیگه رمز مشترک جدا (`DASHBOARD_PASSWORD`) وجود نداره.** ورود به `/dashboard` دقیقاً از همون فرم و همون جدول `users`ی استفاده می‌کنه که `/account` استفاده می‌کنه — یعنی یه ادمین یا برنامه‌نویس با همون شماره موبایل + رمز عبور حساب خودش وارد می‌شه، فقط این‌بار سیستم چک می‌کنه نقشش `admin` یا `developer` باشه. اگه یه مشتری عادی (نقش `customer`) بخواد از `/dashboard` وارد بشه، رمز/شماره‌ش درسته ولی پیام می‌گیره که این حساب دسترسی داشبورد تیم رو نداره.

- ورود از خودِ `/dashboard` (فرم مخصوص، `StaffLoginForm.tsx`) یا از `/account` — تو هر دو حالت، اگه نقش کاربر ادمین/برنامه‌نویس باشه، بعد از ورود مستقیم می‌ره `/dashboard`؛ مشتری‌ها می‌رن `/account`. همین‌طور اگه یه ادمین/برنامه‌نویس لاگین‌شده سر بزنه به `/account`، خودکار به `/dashboard` ریدایرکت می‌شه (و برعکس، مشتری‌ای که سر بزنه به `/dashboard`).

تب‌های `/dashboard` بسته به نقش فرق می‌کنن:

- **ادمین** پنج تب می‌بینه: **سفارش‌ها** (درخواست‌های فرم تماس)، **تیکت‌ها** (تیکت‌های مشتری‌ها)، **کاربران ثبت‌نامی** (فقط مشتری‌ها، با اسم/شماره/تاریخ)، **تیم برنامه‌نویسی** (لیست جدای اعضای تیم — ادمین‌ها و برنامه‌نویس‌ها، با نقششون)، و **چت تیم**.
- **برنامه‌نویس** سه تب می‌بینه: **سفارش‌ها** (تا بدونه چی باید بسازه)، **تیم برنامه‌نویسی**، و **چت تیم**. به تیکت‌های پشتیبانی و لیست مشتری‌ها دسترسی نداره — اون‌ها برای تیم فروش/پشتیبانیه.

### چت تیم

یه چت داخلی و مشترک (نه پیام خصوصی) فقط برای نقش‌های `admin` و `developer`، تو تب «چت تیم». پیام‌ها تو جدول `team_messages` ذخیره می‌شن (`lib/db.ts`: `sendTeamMessage`, `getTeamMessages`). چون این پروژه وب‌سوکت/سرور-پوش نداره، کامپوننت `TeamChat.tsx` هر ۴ ثانیه پیام‌های جدید رو با یه Server Action (`getTeamMessagesAction`) پول می‌کنه — برای یه تیم کوچیک کافیه.

### ساختن حساب ادمین/برنامه‌نویس

هیچ رابط کاربری‌ای برای عوض‌کردن نقش یه حساب نساختیم (عمداً — چون کنترل دسترسی حساسه). یه نفر اول باید عادی تو `/account` ثبت‌نام کنه، بعد با اسکریپت آماده‌ی `scripts/set-role.js` نقشش رو عوض کنی. این اسکریپت جاواسکریپت خالصه (نه TypeScript)، پس برخلاف `lib/db.ts` مستقیم با `node` اجرا می‌شه — نیازی به بیلد یا ts-node نیست. از ریشه‌ی پروژه (همون پوشه‌ای که `package.json` توشه) بزن:

```bash
# لیست همه‌ی کاربرها با آی‌دی و نقش فعلیشون
node scripts/set-role.js list

# نقش رو عوض کن (به‌جای 1 آی‌دی همون کاربر رو از خروجی list بذار)
node scripts/set-role.js set 1 admin
node scripts/set-role.js set 2 developer
```

برای برگردوندن یه نفر به مشتری عادی:

```bash
node scripts/set-role.js set 1 customer
```

## فرم تماس و داشبورد

- تو بخش تماس یه فرم اضافه شده که کاربر می‌تونه اسم، ایمیل، شماره (اختیاری)، نوع پروژه، بودجه‌ی تقریبی (اختیاری) و توضیحات رو بفرسته.
- ارسال فرم از طریق یه **Server Action** واقعی (کد Node.js سمت سرور، بدون نیاز به API route جدا) تو کالکشن `inquiries` روی MongoDB Atlas ذخیره می‌شه.
- برای دیدنشون برو به [http://localhost:3000/dashboard](http://localhost:3000/dashboard) و با حساب ادمین یا برنامه‌نویسیت وارد شو.
- یه فیلد honeypot مخفی هم روی فرم هست که جلوی بات‌های ساده رو می‌گیره.

## دیپلوی روی Vercel

1. پروژه رو به یه ریپازیتوری گیت (GitHub/GitLab/Bitbucket) پوش کن — `.gitignore` مراقبه که `.env.local` و `node_modules` پوش نشن.
2. تو [vercel.com](https://vercel.com) ریپازیتوری رو **Import** کن (فریم‌ورک به‌صورت خودکار Next.js شناسایی می‌شه، نیازی به تغییر تنظیمات build نیست).
3. قبل از دیپلوی (یا بعدش، تو **Settings → Environment Variables**) این دو متغیر رو اضافه کن:
   - `MONGODB_URI` — همون رشته‌ی اتصال Atlas از بخش بالا.
   - `USER_SESSION_SECRET` — یه رشته‌ی رندوم و طولانی (با `openssl rand -hex 32` بساز)؛ **حتماً یه مقدار واقعی بذار**، چون بدون این هر ری‌استارت سرور همه‌ی نشست‌های لاگین‌شده رو باطل می‌کنه.
   - این دو متغیر رو برای هر سه محیط (Production، Preview، Development) ست کن.
4. برای این‌که آپلود عکس بلاگ/پیوست چت هم کار کنه، از **Storage** یه **Blob** Store بساز و به همین پروژه وصلش کن (بخش «آپلود فایل (Vercel Blob)» پایین‌تر رو ببین) — `BLOB_READ_WRITE_TOKEN` خودکار ست می‌شه.
5. دکمه‌ی **Deploy** رو بزن. بعد از اولین دیپلوی موفق، سایتت رو یه لینک `.vercel.app` می‌گیره (و می‌تونی از **Settings → Domains** دامنه‌ی خودتم وصل کنی).
6. چون همه‌ی دیتا رو Atlas و همه‌ی فایل‌های آپلودی رو Blob نگه می‌داره (نه فایل‌سیستم لوکال Vercel)، هر دیپلوی و هر ری‌استارت بدون از دست رفتن دیتا کار می‌کنه.

**نکته درباره‌ی فایل‌های آپلودی:** عکس بلاگ و پیوست/ویس چت تیم از طریق **Vercel Blob** ذخیره می‌شن (نه دیسک لوکال)، پس رو Vercel هم بدون مشکل و بدون از دست رفتن فایل بعد از هر دیپلوی کار می‌کنه — بخش بعدی رو ببین.

## آپلود فایل (Vercel Blob)

عکس کاور بلاگ و پیوست/ویس چت تیم (`lib/uploads.ts`) از **Vercel Blob** استفاده می‌کنن.

**رو Vercel:**
1. تو داشبورد پروژه‌ت برو **Storage → Create Database → Blob** و یه Store بساز.
2. Store رو به همین پروژه **Connect** کن — Vercel خودش متغیر محیطی `BLOB_READ_WRITE_TOKEN` رو براش ست می‌کنه، نیازی نیست چیزی رو دستی کپی کنی.
3. همین. بعد از دیپلوی بعدی، آپلود عکس بلاگ و فایل/ویس چت تیم کار می‌کنه.

**برای اجرای محلی (`npm run dev`):**
- بعد از این‌که پروژه رو با `vercel link` به پروژه‌ی Vercel‌ت وصل کردی، با `vercel env pull .env.local` مقدار `BLOB_READ_WRITE_TOKEN` (به‌همراه بقیه‌ی متغیرهای محیطی که تو Vercel ست کردی) خودکار میاد تو `.env.local`.
- یا دستی از **Storage → (Store‌ت) → .env.local** تو داشبورد Vercel کپی‌ش کن و بذارش تو `.env.local`.
- بدون این توکن، آپلود عکس/فایل با پیام خطا مواجه می‌شه؛ بقیه‌ی سایت (فرم تماس، ورود/ثبت‌نام، تیکت‌ها، چت متنی بدون پیوست) عادی کار می‌کنه.

## نکات فنی

- **TypeScript** روی همه‌ی فایل‌ها فعاله (`strict: true`).
- **Tailwind CSS** برای تقریباً تمام استایل‌ها استفاده شده؛ `darkMode: "class"` فعاله.
- فونت‌ها با `next/font/google` لود می‌شن.
- تم فقط از سه توکن رنگ ساخته شده: `ink`، `dim`، `canvas` — هر سه از طریق CSS variable (`--color-*`) تعریف شدن تا با کلاس `.dark` رو `<html>` خودکار بین حالت روشن و تاریک عوض بشن. پیش‌فرض همیشه روشنه.
- کامپوننت‌های تعاملی (منو، ترمینال، اسکرول‌ریویل، فرم تماس، فرم‌های حساب کاربری، فرم ورود تیم، چت تیم، تعویض تم) با `"use client"` مشخص شدن؛ بقیه سرور-رندر هستن.
- **یه سیستم احراز هویت واحد:** همه‌ی حساب‌ها (مشتری، برنامه‌نویس، ادمین) تو همون جدول `users`ن، با رمز عبور هش‌شده (`scrypt`) و نشست امضاشده با `USER_SESSION_SECRET`. تنها فرقشون ستون `role`ه که کنترل می‌کنه به `/account` دسترسی دارن یا `/dashboard`، و تو `/dashboard` چه تب‌هایی رو می‌بینن.

> چون این پروژه در محیطی بدون دسترسی اینترنت ساخته/ویرایش شده، امکان اجرای `npm install` و تست زنده وجود نداشت — از جمله این دور از تغییرات (تبدیل عکس‌ها به WebP، اتصال Redis، سخت‌گیرتر شدن رمز عبور). کدها استاندارد و بر اساس Next.js 14 App Router + Tailwind v3 + Server Actions نوشته شدن، ولی قبل از دیپلوی حتماً:
> 1. `npm install` رو بزن (این دور یه پکیج جدید یعنی `ioredis` به `package.json` اضافه شده که هنوز تو `package-lock.json` نیست — `npm install`، نه `npm ci`، لازمه تا لاک‌فایل به‌روز بشه).
> 2. `npm run build` رو بزن و مطمئن شو بدون خطا تموم می‌شه.
> 3. `MONGODB_URI` رو ست کن؛ `REDIS_URL` اختیاریه ولی برای فعال شدن واقعی کش/محدودیت نرخ لازمه (بخش «اتصال به Redis» بالا).
> 4. فرم ثبت‌نام (با رمز عبور جدید و نوار قدرت رمز)، فرم تماس، چت تیم، و صفحات عکس‌دار (پورتفولیو، وبلاگ) رو تست کن.
