# راهنمای Migration دیتابیس — «باقلوا کریم اغلو»

## وضعیت قبل از این مرحله (صادقانه)

تا پایان Prompt 14، پروژه اصلاً سیستم Migration نداشت — `lib/db/schema.sql`
فقط با `CREATE TABLE IF NOT EXISTS` یک‌بار روی هر دیتابیس اجرا می‌شد. این
برای «اولین راه‌اندازی» درست کار می‌کند اما هیچ راه امنی برای تغییر Schema
روی یک دیتابیس Production که از قبل سفارش/کاربر واقعی دارد فراهم نمی‌کرد.

## راه‌حل اضافه‌شده در این مرحله

- جدول `schema_migrations` (در خود `schema.sql`، بی‌خطر و Idempotent)
- پوشه `lib/db/migrations/` برای فایل‌های SQL عددی آینده (رجوع به
  `lib/db/migrations/README.md` برای قرارداد کامل نام‌گذاری)
- اسکریپت `scripts/migrate.mjs` — فایل‌های اعمال‌نشده را به ترتیب، هرکدام
  داخل یک Transaction، اجرا و ثبت می‌کند

این در همین چت **واقعاً تست شد** (نه فقط نوشته شد): یک فایل نمونه
`ALTER TABLE users ADD COLUMN ...` ساخته، روی یک دیتابیس تازه اجرا،
ستون/رکورد `schema_migrations` تأیید، و بعد پاک شد (چون نمونه بود، نه
تغییر واقعی موردنیاز کسب‌وکار).

## فرآیند اضافه‌کردن یک Migration جدید

1. یک فایل `NNNN_توضیح.sql` در `lib/db/migrations/` بسازید (عدد بعدی، صعودی)
2. محتوای آن را **فقط روی یک کپی محلی/Staging از دیتابیس واقعی** تست کنید
3. برای تغییرات خطرناک (حذف ستون/جدول، تغییر نوع داده روی جدول پر) — به بخش پایین («Migration خطرناک») مراجعه کنید
4. قبل از اجرا روی Production: `node scripts/backup-db.mjs`
5. اجرا: `node --experimental-strip-types scripts/migrate.mjs`
6. Smoke Test برنامه بعد از Migration

## Migration خطرناک

هر تغییری که **داده موجود را از دست می‌دهد یا برگشت‌ناپذیر است** (مثلاً
`DROP COLUMN`، تغییر نوع یک ستون پر از داده، حذف یک جدول) باید:

- در یک پنجره کم‌ترافیک اجرا شود
- بلافاصله بعد از یک Backup تازه (نه Backup دیشب) اجرا شود
- ترجیحاً به دو مرحله تقسیم شود (مثلاً: ابتدا ستون جدید اضافه و کد هر دو
  ستون قدیم/جدید را پشتیبانی کند، بعد از اطمینان کامل، در یک Migration
  جدا و بعدی ستون قدیم حذف شود) — نه یک Migration یک‌مرحله‌ای که راه
  برگشتی ندارد
- توسط بیش از یک نفر (Code Review واقعی) قبل از اجرا بررسی شود

هیچ Migration خطرناکی فعلاً در این پروژه وجود ندارد — این بخش فقط
راهنمای آینده است.

## Rollback یک Migration

`scripts/migrate.mjs` خودش Rollback خودکار Schema را پشتیبانی نمی‌کند
(یعنی فایل «معکوس» خودکار نمی‌سازد) — روش امن Rollback همان
`docs/restore-guide.md` است: از همان Backup قبل از Migration (مرحله ۴ بالا) Restore کنید.
