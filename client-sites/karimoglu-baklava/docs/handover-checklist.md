# Handover Checklist — «باقلوا کریم اغلو»

هدف: هیچ سرویس حیاتی نباید فقط به حساب شخصی یک نفر (Developer/Freelancer)
وابسته بماند. برای هرکدام، مالک باید یک **حساب سازمانی متعلق به شرکت** (نه
ایمیل شخصی یک نفر) باشد و حداقل ۲ نفر از تیم شرکت به آن دسترسی Admin
داشته باشند.

| مورد | وضعیت فعلی | اقدام لازم |
|---|---|---|
| GitHub / Repository | TODO تیم — این پروژه هنوز مشخص نیست روی چه حسابی است | Repository باید زیر یک GitHub Organization متعلق به شرکت باشد، نه حساب شخصی یک Developer؛ حداقل ۲ نفر از تیم Owner/Admin باشند |
| Server / Hosting | ❌ هنوز انتخاب نشده | حساب Hosting/Cloud زیر ایمیل/کارت شرکت باز شود، نه شخصی |
| Domain / DNS | ❌ هنوز انتخاب نشده | ثبت Domain زیر مالکیت رسمی شرکت (WHOIS/Registrar Account شرکت) |
| Database | فایل روی همان سرور — رجوع به ردیف Server | همراه با Backup خارج از سرور (هنوز TODO) |
| Payment Gateway | ❌ هنوز متصل نشده | حساب Merchant باید مستقیم زیر شرکت باز شود (الزام قانونی/مالی معمولاً همین‌طور است) |
| SMS Provider | ❌ هنوز متصل نشده | حساب زیر شرکت |
| Object Storage / CDN | ❌ هنوز استفاده نمی‌شود | وقتی اضافه شد، زیر همان حساب Cloud شرکت (نه حساب شخصی جدا) |
| Monitoring/Alerting | ❌ هنوز انتخاب نشده | حساب زیر شرکت، دسترسی حداقل ۲ نفر |
| Backup Storage خارج از سرور | ❌ هنوز پیاده نشده | همراه با انتخاب مقصد (بالا، `backup-guide.md`) |
| Environment Secrets (GitHub Environments) | آماده برای تنظیم (`environment-variables.md`) | فقط توسط Admin واقعی Repository شرکت قابل مشاهده/ویرایش باشد — نه در فایل/چت/Slack شخصی رد و بدل شود |
| رمز عبور اولین ادمین Bootstrap | رجوع به `admin-guide.md` | بعد از اولین ورود فوراً عوض و از Secrets حذف شود |

## قبل از پایان همکاری با هر Developer/Freelancer

- [ ] همه کلیدهای SSH شخصی آن فرد از سرور حذف شوند
- [ ] دسترسی GitHub آن فرد به Repository لغو شود (یا به سطح مناسب کاهش یابد)
- [ ] هر Secret/Token که آن فرد ساخته یا دیده (API Key، Environment Secret) Rotate شود
- [ ] حساب ادمین شخصی آن فرد در پنل (اگر ساخته بود) غیرفعال شود؛ رجوع به `incident-response-guide.md` بخش «نشت داده حساس» برای روش دقیق
