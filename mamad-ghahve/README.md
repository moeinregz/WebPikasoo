# ممد قهوه — فروشگاه آنلاین قهوه

Next.js 14 (App Router) + React 18 + Node.js + SQLite (موتور داخلی Node.js: node:sqlite — بدون پکیج native)

## راه‌اندازی

> **استقرار روی لیارا:** راهنمای کامل در [`DEPLOY-LIARA.md`](DEPLOY-LIARA.md) — فایل `liara.json` آماده‌ست.

```bash
cd mamad-ghahve
npm install
cp .env.example .env.local     # SITE_URL و رمز ادمین رو عوض کن
npm run build
npm start                       # http://localhost:3000
```

دیتابیس (`data/shop.db`) اولین بار خودکار ساخته و با محصولات نمونه پر می‌شه.
پنل مدیریت: `/admin` — ورود اول با `ADMIN_USERNAME` / `ADMIN_PASSWORD` از `.env.local` (پیش‌فرض `admin` / `admin123`). بعد از ورود از «تنظیمات» رمز رو عوض کن.

> روی سرور (VPS) اجرا کن، نه هاست‌های serverless مثل Vercel؛ SQLite و عکس‌های آپلودی روی دیسک ذخیره می‌شن (`data/`). از پوشه‌ی `data/` بکاپ بگیر.

## امکانات

**فروشگاه**
- اسلایدر هیرو با جابه‌جایی خودکار هر ۳ ثانیه، نقطه‌ها، فلش‌ها و سوایپ روی گوشی
- ردیف‌های «جدیدترین‌ها»، «محبوب‌ترین‌ها» (بر اساس تعداد فروش)، «تخفیف‌های ویژه»، «پیشنهاد ممد» — روی گوشی با سوایپ و روی دسکتاپ با دکمه‌های قبلی/بعدی
- فروشگاه با فیلتر دسته، جستجو، مرتب‌سازی و فقط تخفیف‌دارها
- صفحه‌ی محصول با انتخاب نوع آسیاب و تعداد
- سبد خرید (ذخیره در مرورگر)، کد تخفیف، هزینه‌ی ارسال و ارسال رایگان بالای یک مبلغ
- همه‌ی قیمت‌ها سمت سرور حساب می‌شن؛ قیمت از مرورگر قبول نمی‌شه
- منوی پایین مخصوص موبایل

**باشگاه مشتریان**
- عضویت/ورود با موبایل و رمز، امتیاز هدیه‌ی عضویت
- امتیاز بعد از هر پرداخت موفق؛ سطح برنزی / نقره‌ای / طلایی با ضریب امتیاز
- خرج کردن امتیاز موقع پرداخت (با سقف درصدی)؛ اگه پرداخت ناموفق بشه امتیاز برمی‌گرده
- صفحه‌ی حساب: کارت عضویت، پیشرفت سطح، تاریخچه‌ی امتیاز، سفارش‌ها، ویرایش پروفایل

**پنل مدیریت** (`/admin`)
- داشبورد فروش، سفارش‌های منتظر ارسال، موجودی کم، پرفروش‌ها
- محصولات: افزودن / ویرایش / حذف، آپلود عکس، ویرایش سریع قیمت و موجودی، فعال/غیرفعال
- دسته‌بندی‌ها، اسلایدها، کدهای تخفیف
- سفارش‌ها: تغییر وضعیت، کد رهگیری پست، ثبت دستی پرداخت (کارت‌به‌کارت)
- مشتری‌ها: سطح، جمع خرید، افزودن/کسر دستی امتیاز
- تنظیمات: فروشگاه، باشگاه، درگاه‌ها، باسلام، رمز مدیر

## درگاه‌های پرداخت و باسلام

همه از «پنل ← تنظیمات» تنظیم می‌شن. هر درگاه دکمه‌ی **«تست اتصال»** داره که بدون پرداخت واقعی، ورود و کلیدها رو چک می‌کنه.
`SITE_URL` باید دامنه‌ی واقعی با https باشه؛ آدرس بازگشت (callback) هر درگاه زیر تنظیماتش نوشته شده.

| سرویس | فایل | چیزی که لازم داری |
|---|---|---|
| زرین‌پال | `lib/payments/zarinpal.ts` | مرچنت کد |
| اسنپ‌پی | `lib/payments/snappay.ts` | آدرس API، Client ID/Secret، Username/Password + ثبت IP سرور پیش اسنپ‌پی |
| دیجی‌پی | `lib/payments/digipay.ts` | آدرس API (تست `uat.mydigipay.info` / اصلی `api.mydigipay.com`)، Client ID/Secret، Username/Password، نوع پرداخت |
| باسلام | `lib/basalam.ts` | توکن دسترسی شخصی (developers.basalam.com/panel/tokens) و شناسه‌ی دسته — شناسه‌ی غرفه با تست اتصال خودکار پر می‌شه |
| درگاه آزمایشی | `lib/payments/mock.ts` | — (قبل از فروش واقعی خاموشش کن) |

**اسنپ‌پی:** token ← eligible ← payment/token ← بازگشت POST (state, transactionId, amount) ← verify ← settle (اگه settle نشه، revert).
شناسه‌ی تراکنش = بخش عددی کد سفارش (۸ رقم). جمع سبد − تخفیف = مبلغ.

**دیجی‌پی:** token (multipart) ← tickets/business?type ← بازگشت POST (result, amount, providerId, trackingCode, type) ← purchases/verify (با تلاش دوباره روی کد 9011).
برای نوع ۵ (اعتباری) و ۱۳ (اقساطی) سبد خرید هم فرستاده می‌شه و با زدن «ارسال شده» روی سفارش، تحویل خودکار به دیجی‌پی اعلام می‌شه.

**باسلام** (API عمومی `openapi.basalam.com/v1`، مطابق SDK رسمی): ساخت محصول `POST /v1/vendors/{id}/products`، ویرایش `PATCH /v1/products/{id}`،
عکس محصول اول با `POST /v1/files` آپلود می‌شه و فقط وقتی عوض شده دوباره آپلود می‌شه. واحد قیمت (ریال/تومان) قابل انتخابه؛
بعد از ارسال اولین محصول قیمتش رو تو باسلام چک کن.

**وضعیت تست:** مستندات رسمی دیجی‌پی، اسنپ‌پی و باسلام از محیط توسعه در دسترس نبود؛ کد بر اساس SDK رسمی باسلام و SDKهای پرکاربرد
دیجی‌پی و اسنپ‌پی نوشته شده و کل جریان خرید/تأیید/تسویه/تحویل و ارسال محصول به باسلام با یک شبیه‌ساز محلی که همین قواعد رو چک می‌کنه
تست شده. قبل از فروش واقعی، با اطلاعات تستی که هر سرویس بعد از قرارداد می‌ده، «تست اتصال» و یک خرید آزمایشی انجام بده.
مسیرهای API بالای هر فایل در `PATHS` جمع شدن تا اگه نسخه‌ی مستندات شما فرق داشت، فقط همون‌جا رو اصلاح کنی.

## ساختار

```
app/(store)/      صفحات فروشگاه (خانه، shop، product، cart، checkout، order، club، account)
app/admin/        پنل مدیریت + server actions
app/api/          quote، checkout، callback درگاه‌ها، سرو عکس‌های آپلودی
lib/db.ts         اسکیمای SQLite  ·  lib/seed.ts  داده‌ی اولیه
lib/orders.ts     محاسبه‌ی قیمت، ثبت سفارش، پرداخت موفق/ناموفق
lib/club.ts       سطح‌ها و امتیاز باشگاه
lib/payments/     درگاه‌ها
components/       اسلایدر، ردیف محصولات، کارت محصول، سبد خرید
```
